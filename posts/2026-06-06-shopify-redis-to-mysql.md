전자상거래 플랫폼을 운영할 때 가장 까다로운 도전 과제는 '재고 관리'입니다. 한정된 수량의 인기 상품을 수만 명이 동시에 구매하려고 결제할 때, 결제는 되었는데 상품이 부족해 배송하지 못하는 '초과 판매(Oversell)'를 막기 위해 모든 쇼핑몰은 결제 중 재고를 잠시 선점해 두는 '재고 예약 시스템'을 운영합니다.

이 분야에서 가장 널리 쓰이는 도구는 데이터를 메모리 상에서 초고속으로 처리하는 Redis였습니다. 많은 트래픽을 빠르게 소화하기에 제격이기 때문입니다. 하지만 세계 최대의 이커머스 솔루션인 쇼피파이(Shopify)는 수년간 성공적으로 운영하던 Redis를 걷어내고, 뜻밖에도 전통적인 관계형 데이터베이스인 MySQL로 시스템을 교체했다는 엔지니어링 리포트를 발표했습니다. 최신 인메모리 아키텍처가 대세인 시대에, 쇼피파이가 MySQL로 돌아간 이유는 무엇일까요?

---

## 1. 분산 데이터 일관성의 한계와 데이터 엇갈림 현상

쇼피파이가 Redis에서 MySQL로 마이그레이션(시스템 전환)을 단행한 결정적인 이유는 **두 개의 저장소를 사용할 때 데이터가 서로 일치하지 않는 문제** 때문이었습니다.

기존 구조에서는 결제 중인 '임시 예약 상태'는 속도가 빠른 Redis에 저장했고, 결제가 완료된 후 '실제 장부 차감'은 영구 저장소인 MySQL에 기록했습니다. 즉, 데이터가 두 군데에 쪼개져 있었습니다.

이로 인해 두 곳의 데이터를 하나로 묶어 처리하지 못해 생기는 싱크 오류(Split-Brain)를 겪었습니다. 네트워크 장애로 인해 MySQL 장부에는 기록되었는데 Redis의 임시 예약이 해제되지 않으면, 실제 제품이 남았음에도 품절로 처리되는 '과소 판매(Undersell)'가 발생합니다. 반대로 Redis 예약은 풀렸는데 MySQL에 최종 기록이 실패하면 초과 판매가 생깁니다. 양쪽 저장소를 하나의 완벽한 거래(ACID 트랜잭션, 원자성 보장)로 묶어 처리할 수 없다는 구조적 한계가 존재했던 것입니다.

---

## 2. MySQL 8의 '건너뛰기(SKIP LOCKED)'로 해결한 병목 현상

이를 해결하기 위해 쇼피파이는 MySQL 8버전의 최신 기능인 **`SKIP LOCKED(락이 걸린 행 건너뛰기)`** 기능을 활용했습니다.

보통 관계형 데이터베이스에서 여러 사용자가 한 데이터를 동시에 수정하려고 하면, 데이터가 꼬이지 않도록 먼저 접근한 사람을 위해 데이터를 잠그는 '락(Lock)'을 겁니다. 이 때문에 다른 사람들은 대기하느라 전체 시스템이 느려지는 병목이 발생합니다. 하지만 `SKIP LOCKED` 쿼리를 사용하면, 이미 다른 사람에 의해 잠겨 있는 데이터를 대기하지 않고 그냥 건너뛰어, 잠기지 않은 다음 사용 가능한 재고 데이터를 즉시 확보할 수 있습니다.

쇼피파이는 상품당 하나로 관리하던 수량 데이터를, 재고 유닛 1개당 하나의 로우(Row, 데이터 행)로 매핑하는 개별 유닛 모델을 도입했습니다. 그 결과 수만 명의 사용자가 동시에 구매 버튼을 눌러도 대기 시간 없이 각자 다른 재고 데이터를 안전하고 원자적으로 확보할 수 있게 되었습니다.

---

## 3. 단순함(Simplicity)이 최고의 확장성이다

쇼피파이의 기술 개편은 현대의 IT 엔지니어들에게 큰 교훈을 줍니다.

첫째, **"단순함이 최고의 성능을 낸다"**는 점입니다. 많은 기술 기업들이 유행을 따라 데이터를 여러 서버에 분산 처리하는 복잡한 시스템을 설계합니다. 하지만 이는 데이터 정합성(일치성)을 깨트려 엄청난 코딩 복잡도와 디버깅 비용을 수반합니다. 쇼피파이는 분산 시스템을 걷어내고, 하나의 관계형 데이터베이스로 일관성을 단일화하여 문제를 완벽히 해결했습니다.

둘째, **진짜 병목은 데이터베이스 성능보다 '네트워크 통신 횟수'**일 수 있다는 점입니다. 쇼피파이는 여러 개별 쿼리를 단 하나의 배치(묶음) 트랜잭션으로 합쳐 데이터베이스 접속 빈도를 극소화함으로써 성능을 최적화했습니다. 최신 분산 캐시 시스템을 무작정 늘리기보다, 우리가 가진 기본 데이터베이스를 잘 이해하고 튜닝하는 것이 더 중요함을 보여줍니다.

---

## 결론: 본질에 집중하는 엔지니어링

쇼피파이 사례는 유행을 따르기보다 해결하려는 문제의 본질(데이터 정합성)에 집중하는 것이 훌륭한 엔지니어링임을 입증합니다.

오늘 다룬 내용을 세 줄로 요약해 보겠습니다:
1. 쇼피파이는 임시 예약(Redis)과 최종 장부(MySQL) 간의 데이터 불일치 문제를 해결하기 위해 시스템을 통합했습니다.
2. MySQL 8의 `SKIP LOCKED` 기능과 개별 유닛 행 모델을 도입하여 락 대기 병목 없이 고성능 동시 처리를 구현했습니다.
3. 이를 통해 시스템의 복잡한 구조를 단순화하고 결제 정합성을 100% 보장하는 안전한 아키텍처를 완성했습니다.

때로는 익숙한 도구를 깊이 이해하고 한계까지 튜닝하는 것이 가장 세련된 솔루션이 됩니다.
