Next.js App Router 환경은 강력한 서버 사이드 렌더링(SSR)과 정적 사이트 생성(SSG) 기능을 제공하지만, 클라이언트 사이드 스크립트 기반인 **구글 애드센스(Google AdSense)**를 적용할 때 종종 Hydration 에러를 발생시킵니다. 

이 포스트에서는 구글 애드센스를 연동하면서 발생하는 오류의 원인과 이를 완벽히 해결하는 안전한 컴포넌트 설계 방법을 설명합니다.

---

## 1. Hydration 에러가 발생하는 원인

Next.js는 서버에서 미리 생성된 HTML 구조를 클라이언트에 전달한 뒤, 클라이언트 브라우저에서 리액트 컴포넌트 트리와 결합하는 **Hydration** 과정을 거칩니다.

### 1.1 서버와 클라이언트의 HTML 불일치
구글 애드센스 스크립트가 로드되면 DOM에 임의로 광고용 `<iframe>` 태그를 삽입하거나 태그 속성을 변경합니다. 이 시점이 리액트가 Hydration을 마치는 시점보다 빠르면 리액트는 "서버에서 렌더링한 HTML과 클라이언트가 렌더링한 HTML이 다르다"는 에러를 던집니다.

### 1.2 광고 스크립트의 실행 타이밍 문제
단순히 `<script>` 태그를 `app/layout.tsx`에 박아놓게 되면, 페이지가 이동될 때마다 광고 코드가 중복 실행되거나 에러가 생기며, 사용성 저하와 광고 비활성화로 이어질 수 있습니다.

---

## 2. 해결 방안: useEffect 기반 클라이언트 마운트

이 문제를 완벽하게 우회하는 가장 좋은 방법은, 컴포넌트가 **완전히 브라우저에 마운트(Client Mounted)된 이후**에만 애드센스 인스턴스를 수동으로 시작해 주는 것입니다.

### 2.1 컴포넌트 초기화 검증
React의 `useEffect` 훅은 오직 클라이언트 브라우저에서만 실행되므로, 이 안에서 광고를 호출하는 `(window.adsbygoogle = window.adsbygoogle || []).push({})` 코드를 작동시키면 서버와 클라이언트 간의 불일치를 피할 수 있습니다.

### 2.2 광고 컴포넌트 설계 방향
- `useClient` 지시어를 사용하여 클라이언트 컴포넌트로 선언합니다.
- 광고를 그릴 준비가 완료되었음을 나타내는 `mounted` 상태(State)를 관리합니다.
- 다크 모드 등 테마 스위칭 시에도 레이아웃이 깨지지 않도록 유연한 CSS 클래스를 적용합니다.

---

## 3. ads.txt 배치의 중요성

광고 수익 손실을 방지하려면 Vercel 배포 시 도메인 루트 경로에 `ads.txt`가 반드시 노출되어야 합니다.

- Next.js에서는 `public/ads.txt` 경로에 파일을 생성하면 빌드 후 자동으로 루트(`https://yourdomain.com/ads.txt`)에 매핑됩니다.
- 본인의 게시자 ID(예: `pub-1234567890123456`)가 정확히 입력되었는지 확인해야 합니다.
