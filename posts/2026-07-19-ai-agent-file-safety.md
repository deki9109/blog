AI 에이전트가 단순한 답변 도구에서 실행 도구로 이동하고 있습니다. 문서를 요약하는 수준을 넘어 파일을 만들고, 코드를 수정하고, 브라우저를 조작하고, 외부 API를 호출합니다. 생산성은 분명히 올라갑니다. 하지만 위험의 성격도 바뀝니다. 챗봇이 틀린 답을 하면 사람이 고칠 수 있습니다. 반면 에이전트가 잘못된 파일을 삭제하거나, 잘못된 브랜치에 배포하거나, 민감한 데이터를 다른 곳으로 옮기면 피해는 즉시 시스템 상태로 남습니다.

![AI 에이전트가 파일 삭제 같은 파괴적 작업 앞에서 권한 게이트와 백업에 막히는 이미지](/images/2026-07-19-ai-agent-file-safety.png)

## 에이전트는 사용자가 아니라 권한 있는 실행자다

AI 에이전트를 사람처럼 대하면 운영 설계가 느슨해집니다. 실제로는 사람보다 더 조심해야 합니다. 사람은 작업 중 이상한 점을 느끼면 멈추는 경우가 많지만, 에이전트는 목표를 달성하려는 방향으로 계속 시도할 수 있습니다. "폴더를 정리해줘"라는 요청을 받은 에이전트가 오래된 파일을 삭제해야 한다고 판단할 수도 있고, "빌드를 고쳐줘"라는 요청에서 설정 파일을 크게 바꿀 수도 있습니다.

이 문제는 모델이 나빠서만 생기는 것이 아닙니다. 목표가 모호하고, 권한이 넓고, 되돌리기 절차가 없으면 좋은 모델도 위험해집니다. 그래서 에이전트 운영의 핵심은 모델 지능이 아니라 실행 경계입니다. 어떤 작업은 읽기 전용으로만 허용하고, 어떤 작업은 diff 미리보기 후 승인받고, 어떤 작업은 절대 자동 실행하지 않도록 나눠야 합니다.

## 파괴적 작업은 별도 경로로 격리해야 한다

파일 삭제, 대량 이동, 데이터베이스 변경, 배포, 결제, 외부 메시지 전송은 일반 작업과 다르게 다뤄야 합니다. 이런 작업은 한 번 실행되면 단순한 텍스트 오류가 아니라 실제 상태 변경이 됩니다. 안전한 구조에서는 에이전트가 먼저 제안만 만들고, 사람이 변경 내용을 확인한 뒤 승인합니다. 승인 전에는 백업 스냅샷이나 롤백 지점이 있어야 합니다.

특히 파일 작업은 위험이 작아 보이지만 실제로는 자주 문제를 만듭니다. 에이전트가 중복 파일을 정리하다가 원본을 지울 수 있고, 임시 파일을 치우다 필요한 캐시나 설정을 지울 수 있습니다. 자동화가 반복 실행되면 작은 오판이 여러 폴더에 확산됩니다. 그래서 파괴적 작업은 별도 승인 큐와 감사 로그를 거쳐야 합니다.

![AI 에이전트 실행에서 읽기 전용 공간, 권한 요청, 백업, 승인, 롤백이 연결되는 구조 이미지](/images/2026-07-19-ai-agent-file-safety-sub.png)

OpenAI가 ChatGPT Agent와 Codex 같은 에이전트 제품에서 사용자 확인, 권한 경계, 샌드박스, 명령 승인 같은 요소를 강조하는 이유도 여기에 있습니다. 좋은 에이전트 경험은 사용자가 계속 감시하지 않아도 되는 것이 아니라, 위험한 순간에 사용자가 정확히 개입할 수 있게 만드는 것입니다.

## 팀이 바로 적용해야 할 운영 기준

실무 팀은 에이전트 도입 전에 최소 기준을 정해야 합니다. 첫째, 기본 권한은 읽기 전용으로 시작해야 합니다. 쓰기 권한은 작업 단위로 열어야 합니다. 둘째, 모든 파일 변경은 diff로 검토할 수 있어야 합니다. 사람이 이해할 수 없는 대량 변경은 자동 커밋하면 안 됩니다. 셋째, 삭제와 이동은 승인 전에는 계획만 생성해야 합니다. 넷째, 자동 실행 전 백업 또는 복구 지점을 만들어야 합니다.

다섯째, 에이전트가 한 일을 로그로 남겨야 합니다. 어떤 요청에서 어떤 파일을 읽었고, 어떤 명령을 실행했고, 어떤 이유로 변경했는지 추적할 수 있어야 합니다. 여섯째, 실패 시 멈추는 기준을 정해야 합니다. 같은 오류를 반복해서 고치려는 시도는 비용과 위험을 동시에 키웁니다. 일곱째, 자동화 계정의 권한을 사람 관리자 계정과 분리해야 합니다.

![개발팀이 AI 에이전트의 파일 변경, 백업, 승인 절차를 검토하는 장면](/images/2026-07-19-ai-agent-file-safety-sub2.png)

결국 오늘의 핵심은 세 가지입니다.

1. AI 에이전트의 위험은 틀린 답보다 실제 시스템을 잘못 바꾸는 데 있습니다.
2. 삭제, 배포, 외부 전송, 데이터 변경 같은 작업은 별도 승인과 롤백 경로가 필요합니다.
3. 에이전트 운영의 품질은 모델 성능보다 권한, 로그, 백업, diff 검토 체계에서 결정됩니다.

AI 에이전트는 더 많은 일을 대신할수록 더 명확한 제한이 필요합니다. 자동화의 목적은 사람이 모든 작업을 직접 하지 않게 만드는 것이지만, 책임까지 없애는 것은 아닙니다. 좋은 운영은 에이전트가 빠르게 움직이게 하는 것이 아니라, 멈춰야 할 때 확실히 멈추게 만드는 것입니다.
